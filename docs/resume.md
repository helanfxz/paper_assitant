# 项目简历 - 智能论文阅读助手

## 项目描述

面向科研学习场景开发智能论文阅读助手，支持 PDF 解析、混合检索、三层记忆系统、跨会话用户偏好与学习笔记管理。通过构建自动化评测流水线持续优化检索链路，系统综合检索 F1 值由 0.67 提升至 0.80，长文本问答质量显著改善。

## 核心亮点

### 1. Harness 架构设计

基于 ReAct 范式构建单循环 Agent Harness，将系统拆分为**四层架构**：

- **App Layer（编排层）**：会话生命周期管理、窗口压缩触发、偏好检测与确认处理
- **Context Layer（上下文层）**：统一组装 system prompt，按固定顺序注入偏好、笔记、记忆
- **Runner Layer（执行层）**：纯 model-tool 执行循环，集成 Hook 生命周期拦截
- **Hook Layer（钩子层）**：横切关注点处理，支持确认机制、进度通知、日志记录

**工程价值**：
- 统一管理 prompt 构建、工具调度、分层记忆注入、错误恢复与会话状态持久化
- 使问答流程从"模型直接回答"升级为"可控制、可恢复、可扩展"的执行链路
- 提升复杂问答场景下的稳定性与工程可维护性

**关键设计**：
- 控制流与业务逻辑分离：harness 层负责控制平面，业务逻辑在工具层
- 统一出口原则：所有系统上下文通过同一个 builder 生成，便于调试和审查
- 分层错误恢复：模型调用和工具执行分别处理，支持退避重试和降级策略

### 2. 混合检索链路优化

构建 **MQE + 向量检索 + BM25 + Rerank** 混合检索链路：

- **父子块切分**：用小块检索（精确），用大块回答（完整上下文）
- **MQE 扩展查询**：用 fast_llm 生成 3 条扩展查询，提高召回率
- **并行召回**：向量检索（语义相似）+ BM25 词法检索（精确关键词）并行执行
- **RRF 融合**：在 child chunk 层融合多路结果，不要求分数在同一尺度
- **Rerank 重排**：用独立 rerank_llm 对父块重新排序，提升精确度

**技术亮点**：
- 持久化 BM25 索引（SQLite 倒排索引），检索时不扫描向量库，提升性能
- 向量检索负责语义召回，BM25 负责精确术语召回（模型名、数据集名、缩写），rerank 负责最后裁决
- 显著提升学术术语和精确关键词场景下的召回率与排序质量

### 3. 三层记忆机制

设计 **Profile Memory / Session Memory / Study Notes** 三层记忆体系：

**Profile Memory（长期偏好）**：
- 跨会话持久化用户偏好（语言、格式、详细程度、关注点）
- 采用 `scope + type` 槽位更新，同槽位新值覆盖旧值，避免冲突偏好
- 每轮全量注入上下文，不做语义检索
- 支持规则筛选 + fast_llm 分类 + 程序层确认的 hybrid 偏好检测流程

**Session Memory（会话记忆）**：
- 短期：最近消息保留在滑动窗口（20 条）
- 长期：超窗后按轮次压缩成摘要，存储到向量数据库
- 按需召回：根据问题语义检索相关会话摘要，支持长对话续航

**Study Notes（学习笔记）**：
- 独立 collection 管理用户主动保存的研究笔记
- 支持跨会话语义检索和 CRUD 操作
- 按相似度和阈值过滤，避免无关笔记注入

**设计亮点**：
- 职责分离：Profile 是状态机（当前生效偏好），Session Memory 是冷上下文（历史摘要），Study Notes 是用户沉淀（高价值笔记）
- 按轮次压缩：避免孤立 tool 消息（API 要求 tool 消息前必须有对应的 assistant(tool_calls)）
- 分层注入：按优先级顺序注入 prompt（Profile > Study Notes > Session Memory）

### 4. 错误恢复机制

构建分层错误恢复体系：

**模型调用恢复**：
- 错误分类：限流、网络抖动、上下文过长、结构化输出不合法、未知错误
- 退避重试：限流和网络错误指数退避重试（1s → 2s → 4s）
- 分场景降级：主模型失败返回明确提示，辅助模型（MQE、压缩、rerank）失败降级继续运行

**工具执行恢复**：
- 查询类工具：失败后不中断对话，区分"没查到内容"和"工具执行失败"
- 写入类工具：更保守，失败后明确告知用户

**工程价值**：
- 不是"吞掉所有错误"，而是统一回答：失败类型、能否重试、如何降级、是否中断
- 把错误处理从业务细节抽出来，变成可解释、可复用的控制面能力

## 技术栈

- **框架**：LangChain、LangGraph（早期）
- **向量数据库**：Qdrant
- **词法索引**：SQLite（BM25 倒排索引）
- **LLM**：OpenAI API（主模型、fast_llm、rerank_llm）
- **前端**：Gradio
- **持久化**：SQLite（会话管理）、JSON（用户偏好）
