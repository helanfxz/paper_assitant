# 学术论文 PDF 阅读 Agent 系统 — 下一阶段优化方案

> 本文档由产品策划 Agent、开发评估 Agent、协调者 Agent 经过 4 轮讨论（提案 → 评估 → 修正 → 亮点审查）后收敛形成。

---

## 一、项目下一阶段的核心定位

当前系统已完成 Agent Harness 框架和 PDF 解析模块，但它不应该只是一个"能问答 PDF 内容的 RAG 工具"。

下一阶段的定位是：**帮助用户读懂论文论证结构、评判论文可信度、跨论文体系化理解知识**——从"论文说了什么"升级到"理解论文的智识骨架、评价论文说得对不对、把多篇论文串联为知识体系"。

当前阶段最应该聚焦的能力：
- **论文结构理解**：不只是 chunk 检索，而是理解章节、论据、实验、图表之间的逻辑关系
- **Agent 编排阅读流程**：多步骤推理、跨文档对比、自适应解释深度——体现 Agent Harness 的差异化价值
- **知识建构而非信息提取**：帮助用户沉淀为结构化笔记，而非只输出回答

---

## 二、最终推荐的 4 个优化方向

### 方向一：多论文对比矩阵（Cross-Paper Comparison Matrix）【核心亮点】

1. **方向名称**：多论文对比矩阵

2. **解决的用户痛点**：阅读多篇论文时无法快速对比问题定义、方法路径、数据集、指标；不知道论文之间的结论是否矛盾、方法是否互补

3. **核心功能描述**：在对比工作区放入 2+ 篇论文，Agent 自动按维度（问题定义 / 方法路径 / 数据集 / 评测指标 / 宣称贡献）抽取并生成结构化对比矩阵。用户可展开任意单元格查看原文支撑。后续增强版支持 Agent 主动标记矛盾点和互补机会。

4. **典型使用流程**：
   - 用户将多篇论文加入对比工作区
   - Agent 分别构建各论文的论证片段
   - Agent 对齐"问题 / 方法 / 数据 / 指标"四维，生成对比矩阵表格
   - 用户点击单元格查看原文支撑
   - （增强版）Agent 高亮结论矛盾和方法互补之处
   - 支持导出对比报告用于文献综述

5. **MVP 实现方式**：2 篇论文，纯 Agent 编排，无前端图形依赖。Agent 分别提取论证片段 → 对齐四维度 → 生成 Markdown 矩阵表格 → 单元格关联原文 chunk（利用现有 parent-child chunking + 检索管线）

6. **后续增强版本**：N 篇同时对比；Agent 主动检测矛盾点和方法互补机会（L1：数值矛盾，L2：结论性矛盾）；导出文献综述片段

7. **需要新增的模块**：
   - `agent/cross_paper.py`：对比编排器，负责维度对齐和矩阵生成
   - 对比工作区 session state（复用 Agent Harness session）
   - 维度抽取 prompt template（利用现有 fast_llm + recovery_manager）

8. **与现有模块的关系**：
   - 复用 PDF 解析的 parent-child chunking、证据元数据(page_number/content_source/confidence)
   - 复用 search_pdf 的 RRF + rerank 检索管线定位原文
   - 依赖 Agent Harness 的任务分解和工具编排

9. **是否体现 Agent Harness 价值**：是。跨文档一致性推理、维度自适应选择、多步工具调用——这是 Agent vs 纯 RAG 管线的根本差异

10. **是否体现论文结构理解**：是。依赖 IMRaD 结构理解，按"问题 / 方法 / 实验 / 结论"维度对齐

11. **实现难度**：中。核心逻辑在维度对齐的 prompt 设计，不涉及新的基础设施

12. **推荐优先级**：P0 — 最高优先级，适合作为当前阶段首要目标

13. **为什么适合当前阶段**：高频刚需、痛点明确、充分利用现有模块能力、成功标准清晰（对比矩阵是否正确对齐）

14. **简历亮点**："设计并实现跨文档结构化对比推理系统，通过 Agent 编排实现多篇论文学术维度的自动对齐与矛盾检测"——体现 Agent 编排 + 跨文档推理 + 学术场景理解

---

### 方向二：论文反向提纲增强版（Reverse Outline + Agentic Note）【核心亮点】

1. **方向名称**：论文反向提纲增强版（Reverse Outline + Agentic Note）

2. **解决的用户痛点**：读完论文后难以沉淀为自己的笔记和知识；读论文时看不懂整体脉络；笔记孤立、脱离论文结构语境

3. **核心功能描述**：Agent 执行三步循环（section_segment → rhetorical_label → consistency_check）生成带修辞功能标记的层级反向提纲。每个提纲节点链接原文段落、图表、公式。用户在节点上添加个人批注后，Agent 监控批注中出现的概念，主动检测论文其他部分的相关内容并推送关联提示。批注以"论文结构为骨架"保存，形成结构锚定的知识建构。

4. **典型使用流程**：
   - 上传论文 → Agent 自动执行三步标注循环生成反向提纲
   - 提纲节点带功能标记：`[研究空白]` `[方法提出]` `[设计选择论证]` `[主要结果]` `[局限性]`
   - 用户浏览提纲快速把握框架，展开感兴趣的节点精读原文
   - 用户在节点上添加批注 → Agent 检测批注中的概念词
   - Agent 主动推送：该概念在论文其他部分（方法/实验/讨论）的出现位置
   - 后续问答优先检索批注层和提纲结构层
   - 导出为带引用的 Markdown，直接用于文献综述写作

5. **MVP 实现方式**：Agent 执行三步循环：
   - Step 1 `section_segment`：基于 page_number + IMRaD 启发式拆分章节段
   - Step 2 `rhetorical_label`：对每个段打修辞功能标签（利用现有 fast_llm + structured output）
   - Step 3 `consistency_check`：检测段落到上一层的功能和连续性是否自洽
   
   批注存储复用现有 memory 模块的多级索引。概念关联通过现有 BM25 词汇索引 + 向量检索实现。

6. **后续增强版本**：批注导出为文献综述段落模板；多篇提纲并行对比（与方向一联动）；Agent 根据批注历史生成个性化阅读摘要

7. **需要新增的模块**：
   - `agent/reverse_outline.py`：三步标注循环编排器
   - 提纲 + 批注的持久化 schema（JSON，存于 paper profile）
   - rhetorical label 的 structured output schema（复用 DocumentMetadataExtractionResult 的 recovery 模式）

8. **与现有模块的关系**：
   - 复用 PDF 解析的 page-level metadata（page_number / page_type / content_source）
   - 复用 parent-child chunking（提纲节点指向 parent chunk 保持完整上下文）
   - 复用 lexical_index 做概念追踪；复用 memory 模块做批注存储
   - 原"论证链导航"方向的核心能力（IMRaD 标记）作为基础设施注入本方向

9. **是否体现 Agent Harness 价值**：是。三步标注循环 + 批注意义锚定监控 → 多步骤推理 + 持续状态追踪 + 主动推送，体现 Agent 的主动性

10. **是否体现论文结构理解**：是。以论文自身逻辑结构为骨架，所有批注锚定在结构节点上

11. **实现难度**：中。核心在 rhetorical labeling 的 prompt 质量和 consistency check 的逻辑设计

12. **推荐优先级**：P0 — 最高优先级，与方向一并列为当前阶段双核心

13. **为什么适合当前阶段**：解决"读后即忘"的高频痛点；与方向一形成"先理解单篇 → 再跨篇对比"的递进体验；批注层为后续所有功能提供用户数据基础

14. **简历亮点**："设计基于修辞标注 Agent 的论文反向提纲系统，通过三步循环（分段→标注→一致性校验）将论文阅读从被动浏览升级为主动知识建构"——体现 Agent workflow 设计 + NLP 标注 + 产品思维

### 方向三：公式-实验-结论联动解释 MVP（F-E-C Triangulation）

1. **方向名称**：公式-实验-结论联动解释

2. **解决的用户痛点**：不知道某个公式或图表在论文中起什么作用；不清楚方法、实验、图表之间的关联；读不懂实验结果说明了什么

3. **核心功能描述**：用户用自然语言描述论文中的某个公式或图表，Agent 自动定位 → 向后追溯符号定义和使用语境（upstream）→ 向前追踪哪些实验验证了该公式/图表（midstream）→ 解释该公式/图表最终支撑了论文的哪个结论（downstream）。形成"数学形式 → 实证验证 → 论点支撑"的三段式解释。Agent 自适应追溯深度——核心公式详细展开推导链，引用已有工作的公式做简要对比。

4. **典型使用流程**：
   - 用户在阅读论文时询问："第二个损失函数的正则化项在论文里起什么作用？"
   - Agent 基于 OCR 文本匹配定位公式位置
   - 向后追溯：符号定义、方法部分的使用语境
   - 向前追踪：实验部分的验证（消融实验、对比实验中的该公式相关行）
   - 输出三段式解析（upstream / midstream / downstream）
   - 可进一步展开查看相关实验数据

5. **MVP 实现方式**：纯文本交互，绕过前端"点击选中公式"需求。用户用自然语言描述公式（"第二个损失函数"、"公式(3)"），Agent 利用 OCR 文本 + BM25 词汇索引定位，然后执行 upstream/midstream/downstream 三段式检索。输出纯文本，不依赖图形界面。

6. **后续增强版本**：前端支持点击选中公式/图表区域；推导链可视化；消融实验表格联动展示；跨论文公式符号对齐

7. **需要新增的模块**：
   - `agent/formula_tracer.py`：公式定位 + 三段式追溯编排器
   - 公式/图表到 page_number 的索引增强（利用现有 OCR 文本和 evidence metadata）

8. **与现有模块的关系**：
   - 复用 OCR 引擎的文本提取结果
   - 复用视觉分析模块的图表描述结果
   - 复用跨页段落链接（next_parent_id / prev_parent_id）进行上下文追溯
   - 复用 search_pdf 的检索管线定位相关内容

9. **是否体现 Agent Harness 价值**：是。自适应追溯深度 + 多步工具调用 + 上下文推理

10. **是否体现论文结构理解**：是。直接利用方法-实验-结论的 IMRaD 结构进行上下游追踪

11. **实现难度**：中低。核心是 prompt 设计和检索管线组合，不涉及新基础设施

12. **推荐优先级**：P1 — 第二优先级，可在 P0 两个方向基本成型后启动

13. **为什么适合当前阶段**：充分利用已有模块能力（OCR + 视觉 + 跨页链接），MVP 绕开前端依赖可快速验证

14. **简历亮点**：非核心亮点，但体现 Agent 工具编排 + 多步推理的工程能力

### 方向四：实验结论可信度 Checklist（Claim Credibility Checklist）

1. **方向名称**：实验结论可信度 Checklist

2. **解决的用户痛点**：读不懂实验结果说明了什么；无法判断论文核心主张是否站得住脚；缺少批判性阅读的工具支撑

3. **核心功能描述**：Agent 识别论文核心宣称（claims），根据论文类型（方法论文 / 数据集论文 / 理论论文 / 应用论文）动态生成结构化 checklist，每个检查项附带原文段落引用和典型问题提示。用户逐项检查，Agent 辅助定位原文证据。系统只提供检查框架，不做自动评分——训练用户的批判性阅读能力，而非代替判断。

4. **典型使用流程**：
   - 上传论文 → Agent 识别核心 claims
   - Agent 根据论文类型动态生成 checklist：
     - 方法论文 → 消融是否完备？Baseline 是否公平？指标是否多维度？统计显著性？
     - 数据集论文 → 数据来源是否可靠？标注质量如何？分布是否合理？隐私合规？
   - 每个检查项附带：原文段落引用 + "典型问题提示"（如："很多论文只消融了模块A而跳过了B"）
   - 用户逐项检查，Agent 辅助定位原文
   - 用户自行判断，形成个人评价笔记

5. **MVP 实现方式**：Agent 识别 claims → 论文类型分类 → 动态生成 checklist（检查项 + 原文引用 + 提示）→ 纯文本输出。不做自动评分，降低幻觉风险。

6. **后续增强版本**：领域特定 checklist 模板库；用户 check 历史形成阅读档案；batch 多篇 check 横向对比

7. **需要新增的模块**：
   - `agent/credibility_checklist.py`：claim 提取 + checklist 生成器
   - 论文类型分类器（方法/数据集/理论/应用四类）
   - checklist 模板系统（可配置的检查项集合）

8. **与现有模块的关系**：
   - 复用 PDF 解析的全文内容
   - 复用 search_pdf 的证据定位
   - 复用 Agent Harness 的结构化输出 + 错误恢复

9. **是否体现 Agent Harness 价值**：是。动态 checklist 生成 + 论文类型自适应 + 多步证据定位

10. **是否体现论文结构理解**：是。需要理解 claim 与实验、baseline、消融之间的支撑关系

11. **实现难度**：中。核心在论文类型分类 + 动态 checklist 生成的 prompt 设计

12. **推荐优先级**：P2 — 第三优先级，适合作为后续扩展方向

13. **为什么适合后续做**：批判性阅读是学术最高层次，但 checklist 质量高度依赖对论文的深入理解。更适合在 P0 方向（提纲理解 + 跨论文对比）稳定后，基于更成熟的论文结构解析能力来构建

14. **简历亮点**：择机亮点。"AI 辅助批判性阅读"这个概念有辨识度，但需要谨慎包装避免"AI 能评估论文"的过度承诺——核心是"提供检查框架，人做判断"

## 三、被放弃或延后的方向

### 1. 论证链导航（完整有向图版本）→ 收缩并入方向二

**为什么看起来有价值**：构建论文的问题→假设→方法→实验→结论逻辑依赖图，支持反向追溯和前向推导，是最直观的"论文结构理解"表达方式。

**为什么收缩**：完整有向图构建需要 LLM 对论文进行深度的因果关系推理，在 chunk 级别做边连接面临精度瓶颈，且当前阶段缺乏验证论证图正确性的评测手段。完整版需要前端图形渲染支持。

**收缩后去向**：核心的 IMRaD 标记能力作为基础设施注入方向二（反向提纲），论证图的完整有向图版本延后到下一阶段。

---

### 2. 可信度自动评分 → 收缩为 Checklist

**为什么看起来有价值**：自动给论文每个宣称的可信度打分，看起来是 AI 能力的亮点展示。

**为什么收缩**：可信度自动评分要求 LLM 像领域专家一样判断实验设计质量，在当前 LLM 能力下容易产生幻觉和不可靠评分。评分结果若误导用户（尤其科研新手），负面影响大于价值。checklist 模式更务实——AI 提供框架和定位，人做判断。

**收缩后去向**：已收缩为方向四的 Checklist 版本。

---

### 3. 完全自动生成综述

**为什么看起来有价值**：输入 N 篇论文自动输出文献综述，是科研用户的明确需求。

**为什么当前不优先做**：
- 综述质量难以保障，容易变成"论文摘要拼接"
- 需要跨论文深度理解（矛盾检测 + 方法演进脉络 + 知识图谱），这些基础能力尚未就绪
- 输出物的正确性验证成本高

**后续可行性**：当多论文对比矩阵和反向提纲功能成熟后，基于对比矩阵 + 用户批注自动生成初稿综述段落是合理的增强方向。

---

### 4. 大规模论文知识图谱

**为什么看起来有价值**：构建论文-方法-数据集-作者的实体关系网络，支撑论文搜索和推荐。

**为什么当前不优先做**：
- 实体消歧和关系抽取在学术论文场景下的准确率是核心瓶颈
- 需要大量论文数据才有价值，单用户场景 ROI 低
- 当前阶段应聚焦"帮用户读懂已上传的论文"，而非构建全量论文网络

**后续可行性**：当用户积累了较多已读论文后，在小范围内（用户已上传的所有论文）构建轻量实体共现网络是合理的增强。

## 四、实施路线图

```
Phase 1（当前 — P0 并行）
├── 方向一 MVP：2篇论文对比矩阵 → 4周
│   ├── Week 1-2：维度抽取 prompt + 对齐逻辑
│   ├── Week 3：矩阵生成 + 原文关联
│   └── Week 4：测试 + 边界情况处理
│
└── 方向二 MVP：反向提纲 + 批注锚定 → 4周
    ├── Week 1-2：三步标注循环（segment → label → check）
    ├── Week 3：批注存储 + 概念监控推送
    └── Week 4：导出 + 集成测试

Phase 2（P1 — 方向三）
└── 公式联动解释 MVP → 3周
    ├── Week 1：公式定位 + 检索链路
    ├── Week 2：三段式解析生成
    └── Week 3：自适应追溯深度 + 测试

Phase 3（P2 — 方向四 + 增强）
├── 可信度 Checklist MVP → 3周
├── 方向一增强：N篇对比 + 矛盾检测
└── 方向二增强：多篇提纲并行 + 个性化摘要
```

## 五、讨论过程摘要

本文档由 3 个 Agent 角色通过 4 轮结构化讨论生成：

| 轮次 | 角色 | 产出 |
|---|---|---|
| 第一轮 | 产品策划 Agent | 提出 5 个候选方向（论证链导航 / 可信度评估 / 对比矩阵 / 公式联动解释 / 反向提纲） |
| 第二轮 | 开发评估 Agent | 逐项工程可行性评估，指出论证链导航成本过高、可信度评分不可靠等风险 |
